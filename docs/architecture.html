Architecture Overview

Dependency Injection Pattern

Every data-access service follows the same injection pattern using Drizzle ORM with a custom DI token.

1. Provider Factory (drizzle.provider.ts)

export const DrizzleProvider = { provide: "DRIZZLE_DB", useFactory: async () => { const pool = new Pool({ connectionString: process.env.DATABASE_URL }); return drizzle(pool, { schema }); }, };

2. Module Registration (database.module.ts)

@Module({ providers: [DrizzleProvider], exports: [DrizzleProvider], // available to importing modules }) export class DatabaseModule {}

3. Service Injection (e.g., computers.service.ts)

@Injectable() export class ComputersService { constructor( @Inject('DRIZZLE_DB') private readonly db: NodePgDatabase ) {} async create(dto: CreateComputerDto) { const [created] = await this.db .insert(computers) .values(dto) .returning(); return created; } }

4. Feature Module (computer.module.ts)

@Module({ imports: [DatabaseModule], // gives access to DRIZZLE_DB controllers: [ComputersController], providers: [ComputersService], }) export class ComputersModule {}

Database Architecture

PostgreSQL + Drizzle

The database runs in Docker (PostGIS 16 + pgvector). Schemas are defined with Drizzle ORM in TypeScript, and migrations are generated via drizzle-kit.

Pipeline Details

StageComponentDescription

2Global ValidationPipeValidates request body against DTO with whitelist: true -- strips unknown properties

PXE Boot Flow

Network Boot

How diskless clients boot over the network using iPXE and iSCSI.

Step 1: DHCP + iPXE Chainload

Client powers on
→
DHCP server
→
Downloads ipxe.efi
→
Boots iPXE

DHCP provides the client with the ipxe.efi bootloader served from the /files/ directory.

Step 2: iPXE Initial Script (autoexec.ipxe)

#!ipxe dhcp chain http://192.168.2.1/boot?mac=${net0/mac}

iPXE gets DHCP lease, then chains to the server's /boot endpoint passing its MAC address.

Step 3: Server Generates Boot Script

GET /boot?mac=XX:XX:XX:XX:XX:XX
→
PxeHttpController
→
Lookup by MAC
→
Generate iPXE script

If computer found:

#!ipxe dhcp echo Booting {computer.name} set net0/gateway 0.0.0.0 set keep-san 1 set root-path iscsi:192.168.2.1::::iqn.2025-12.local.pccontrol:{name} sanboot ${root-path} boot

If unknown MAC:

#!ipxe echo Unknown computer {MAC} sleep 10 reboot

Step 4: iSCSI Boot

iPXE client
→
iSCSI target (192.168.2.1)
→
Boots from iSCSI disk

Client uses sanboot to boot from the iSCSI target. The IQN is dynamically constructed as iqn.2025-12.local.pccontrol:{computer_name}.

Wake-on-LAN Flow

Power Management

Turn On (Magic Packet)

POST /wol/turn-on
→
PcController
→
PcService.turnOn()
→
child_process.spawn()
→
PowerShell wol2.ps1

PowerShell command:

powershell.exe -ExecutionPolicy Bypass -File scripts/wol2.ps1 -Mac {mac}

What wol2.ps1 does:

  1. Parses MAC address (strips colons/hyphens/dots)
  2. Creates magic packet: 6 bytes of 0xFF + MAC repeated 16 times
  3. Sends via UDP to broadcast address 255.255.255.255:9

Turn Off (Remote Shutdown)

POST /wol/turn-off
→
PcController
→
PcService.turnOff()
→
child_process.spawn()
→
PowerShell shutdown.ps1

PowerShell command:

powershell.exe -ExecutionPolicy Bypass -File scripts/shutdown.ps1 -Computer {ip}

Scripts & Tooling

scripts/wol2.ps1 -- Wake-on-LAN

PowerShell function Send-WakeOnLan that sends UDP magic packets.

ParameterTypeDefaultDescription
-MacAddressstring--Target MAC (any format)
-BroadcastAddressstring255.255.255.255UDP broadcast target
-Portint9UDP port

Packet format: 6x 0xFF + 16x MAC bytes = magic packet

scripts/StartSession.ps1 -- iSCSI Session Manager

PowerShell function Start-IscsiClientSession for automated iSCSI target setup.

ParameterDescription
-ComputerNamePC name (used as target/VHDX name)
-MACAddressFor WoL integration
-VHDXDirectoryDifferencing VHDX storage path
-BaseVHDXPathGold image path
-WoLScriptPathPath to wol2.ps1

files/ -- PXE Boot Files

FilePurpose
